# 키워드 조사 — 판단 이력 (v1~)

**이 문서는 한 번 쓰고 끝나는 보고서가 아니라 누적 기록이다.** 아래로
계속 v2, v3… 이 붙는다. **앞을 고치지 않고 뒤에 덧붙인다** — 판단이 왜
바뀌었는지가 근거이기 때문이다. 결론이 뒤집히면 새 절에서 뒤집었다고 쓴다.

## 키워드 일을 누가 맡나 (헷갈리면 여기부터)

| | 무엇 | 어디 |
|---|---|---|
| **도구** | 숫자를 어떻게 가져오나 (연관어·검색량·입찰가) | `keyword-tools` 스킬 |
| **판정** | 무엇을 왜 골랐나 · 무엇을 왜 접었나 | **이 문서** |
| **실행** | 오늘 어느 글을 쓰나 | `jupocket-daily` 스킬 1단계 |
| **확인** | 실제로 뭐가 검색에 걸렸나 | `jupocket-seo` 스킬 |

한 바퀴로 돈다:

```
keyword-tools (발굴·조회)  →  이 문서 (판정)  →  jupocket-daily (글)
      ↑                                                  ↓
      └────────────  jupocket-seo (몇 주 뒤 확인)  ←──────┘
```

`jupocket-seo` 가 "이 검색어가 실제로 걸렸다/안 걸렸다"를 들고 오면 그게
다음 판정의 입력이다. **확인 결과도 이 문서에 새 절로 남긴다** — 안 남기면
같은 키워드를 또 후보로 올린다.

## v1 — 네이버 데이터랩 상대 관심도 (2026-08-06)

작성 2026-08-06 · 방법: 네이버 데이터랩(상대 검색 추이) + 네이버 웹문서 SERP 구성

## 방법과 한계 (먼저 읽을 것)

- **절대 검색량은 이 조사에 없다.** 네이버 공개 API는 절대량을 안 준다 — 그건
  네이버 검색광고 **키워드도구**(searchad)에서 뽑아야 한다(보험 프로젝트의 GKP와
  같은 위치). 아래 숫자는 전부 **상대 관심도**다.
- 기준(anchor) = `퇴직금 계산기`. 세 배치 모두에 넣어 배치 간 비교가 되게 했다.
  아래 값은 anchor의 12개월 평균을 100%로 놓은 상대치.
- SERP는 후보 전체가 아니라 우선 2건만 직접 확인했다(연차수당·프리랜서3.3).
  나머지는 관심도만 확정, SERP는 채택 전 확인 필요.

## 2. SERP 경쟁 (직접 확인 2건)

### 프리랜서 3.3 계산기 — ✅ ADOPT (약한 SERP = 틈)
- 문서 총량 **18.9만** (연차수당 180만의 1/10 — 경쟁 얕음)
- 상위: withholding.kr · k-calc.com · pluuug · jongso.ryunadb.kr · savingtax.kr ·
  calcwolrd — **거의 전부 소규모 독립 계산기 사이트.** 네이버·토스·사람인 벽 없음
- **신규 사이트가 랭킹 가능한 명백한 증거.** 5월 종소세 환급철과 엮여 재방문성,

### 연차수당 계산기 — 🟡 WATCH (혼잡)
- 문서 총량 180만
- 상위: 노동OK(nodong.kr) · 사람인 · 고용노동부 노동포털 등 **권위 사이트 존재**,
  단 glasswallet·work.calculate.co.kr 등 소규모도 랭킹 = 깊이로 진입 여지는 있음

## 3. 판정 — SERP 틈 전략의 스위트스팟

**head 노동/급여 계산기(퇴직금·연봉실수령·실업급여·4대보험·주휴수당)는
관심도 최상위지만 네이버 자체 계산기·토스·사람인·노동OK가 점령 → 신규 사이트
정면 승부 불리.** 보험에서 head term 피한 것과 같은 논리.

**틈이 확인된 축 = 프리랜서 3.3% / 종합소득세 환급 클러스터:**
- 관심도 중간(~8%)이지만 SERP가 소규모 사이트뿐(약함)
- 5월 신고철 재방문 + 프리랜서 증가 = 상승 추세
- "환급액 얼마?"는 값을 넣어야 나오는 산출물 → AIO/검색답변이 대체 못 함

**확인 필요(관심도는 있으나 SERP 미확인):** 양도소득세(~28)·취득세(~17)·
증여세(~8)·상속세(~3.3) — 부동산/자산세는 복잡해 세무사 블로그·전문 계산기
사이트(부동산계산기·셀리몬)가 나눠 갖는 경향. 네이버 직접 점령은 덜해 틈 가능성.
채택 전 SERP 확인 요.

## 4. 권장 다음 단계

1. **1차 클러스터 후보 = 프리랜서 3.3% / 종소세 환급** (SERP 틈 확인됨)
2. 부동산/자산세(양도·증여·상속·취득) **SERP 4건 추가 확인** → 틈이면 2차 클러스터
3. 절대 검색량은 **네이버 검색광고 키워드도구**에서 위 shortlist를 뽑아 교차검증
   (보험 GKP처럼) — 상대 관심도만으로는 규모 확정 불가
4. 그 뒤 브레인스토밍 재개: MVP 규모·도메인·애드센스 계정·세율 갱신 구조 확정 →
   설계 문서 → 구현 계획

**퇴직금계산기는 볼륨 최대(29만/5만)인데 입찰가 ₩17 = 클릭당 수익 사실상 0.**
반면 3.3%/종소세 클러스터는 **₩1,300~3,300** — 100배 이상. **head 계산기는 경쟁만
높은 게 아니라 돈도 안 된다.** 회피 결정이 수익 측면에서 재확인됨.

### 네이버 vs Google 분업
- **계산기 키워드는 네이버가 큼**(원천징수 네이버 2,500 vs Google 500) → 네이버 유입
- **개념/설명 키워드는 Google이 큼**(종합소득세 세율·신고대상·인적공제 각 Google 5,000,
  네이버 계산기 pull엔 없음) → **Google 유입 + AdSense 수익의 핵심**

### 최종 결론 (3축 확정)
1. **플래그십 3.3%/종소세 클러스터** = 이길 수 있음(약한 SERP) + 볼륨 있음 +
   **CPC 높음(₩1,900~3,300)**. 세 축 모두 통과.
2. **설명 콘텐츠(개념 글)** = Google 볼륨 5,000 + CPC ₩1,300~1,700. 지원이 아니라
   **Google 유입·수익 엔진**. spec의 설명 콘텐츠 층을 격상 — 계산기와 동급 우선.
3. **head 계산기(퇴직금·실업급여·시급)** = 高볼륨이나 경쟁+저CPC(₩17~28). 최종 회피.

→ 계산기(네이버 유입·참여) + 설명 콘텐츠(Google 유입·고CPC 수익) + PNG 공유(성장)
   세 층이 서로를 먹여살리는 구조가 데이터로 뒷받침됨.

## v6 — 대출·카드 축을 열 것인가 (2026-09-15)

**질문**: 광고 단가가 높은 쪽으로 글을 쓰자. 대출·카드로 가도 되나?

**결론: 축을 옮기지 않는다. 대신 세금 안쪽의 고단가 칸을 판다.**
근거는 CPC가 아니라 **경쟁과 근거**다. 아래 숫자가 그 이유다.

### 어떻게 뽑았나

Google Ads API 는 refresh token 이 만료돼(`invalid_grant`) 못 썼다. 재발급은
브라우저 OAuth 동의가 필요하다 — 사람이 해야 한다. 그래서 8월과 같은 방식,
**키워드 플래너를 브라우저로 직접** 열어 읽었다(대한민국·한국어,
2025년 9월~2026년 8월). 계정 `768-311-4823`.

> 이 계정은 운영중지 상태라 검색량이 구간("1천~1만")으로만 나온다.
> 입찰가는 정상 표시된다.

`scripts/google_ads_client.py` 에 입찰가 두 열(`low_bid`·`high_bid`)을
추가해 뒀다 — 토큰이 살아나면 API 로도 같은 값을 받는다. 예전 스크립트는
검색량·경쟁도만 뽑아서, **볼륨은 큰데 돈이 안 되는 키워드**를 거르지

### 숫자가 말하는 것

1. **CPC 차이가 생각만큼 크지 않다.** 머리 키워드끼리 비교하면 대출
   ₩1,000~4,000 대, 세금 ₩1,300~3,300 대다. 겹친다.
2. **1.5만원짜리는 검색량이 10~100이다.** 월에 몇 번 검색되는 말이다.
   입찰가만 보고 고르면 아무도 안 오는 글을 쓰게 된다 — v3 에서 반대
   방향으로 겪은 함정(퇴직금계산기 월 29만 · 입찰가 ₩17)과 같은 실수다.
3. **볼륨은 대출이 10배 크다** (1만~10만 vs 5천). 이건 사실이다.
4. **그런데 입찰가가 비싼 이유가 곧 못 들어가는 이유다.** 돈이 되니까
   은행·핀테크·비교 사이트가 전부 거기 있다. 도메인 나이 4일, 색인 9개인
   사이트가 설 자리가 아니다.
5. **우리에게 근거가 없다.** 세금은 법령 원문과 계산 함수로 "왜 이 숫자인가"
   를 증명할 수 있다. 대출은 "어디가 금리 싼가"인데 그건 실시간 상품
   데이터고 우리는 갖고 있지 않다. 근거 없이 쓰면 이 사이트의 유일한
   차별점을 버리는 것이다.

곧 가액이라 그 칸이 안 보이는데, 부동산은 그 칸에서 전부가 갈린다.

v6 이 대출 축을 접은 다섯 번째 이유가 **"우리에게 근거가 없다"** 였다.

- **고용노동부장관 고시** — 휴업·재난의 사유·한도, 대출 원리금 상환 인출 사유
- **필요 서류·신청 절차** — 조문에 없고 사업자마다 갈린다
- **연금저축 담보대출** — 근거법이 다르다(소득세법·조특법)

`rates` 의 `notVerified` 에 다섯 항목을 그대로 적어 두고, 글에서도 한 절을
할애해 "왜 우리가 금리를 말하지 않는가"를 밝혔다.

### 카드에서 배운 것 — 목록 7줄은 안 들어간다

사유 7개를 `list` 카드에 그대로 넣었더니 **footnote 가 잘렸다.**
파산선고와 개인회생을 한 줄로 합쳐 6줄로 줄이니 맞았다. `list` 카드의
실질 상한은 **6줄**이다(detail 한 줄씩 딸린 경우).

이때 테스트도 같이 고쳤다. 처음엔 `items.length === reasons.length` 로
검사했는데, 그건 **레이아웃 사정을 법의 사정인 것처럼 굳히는 검사**였다.
"일곱 개 호의 낱말이 카드 어딘가에 다 있는가"로 바꿨다 — 줄 수는 줄여도
되지만 사유가 빠지면 안 되기 때문이다.
