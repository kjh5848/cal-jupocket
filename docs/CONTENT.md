# 콘텐츠 제작 순서

글 한 편을 세상에 내보내는 열 단계. 이 순서대로만 하면 된다.

```
①주제 선정·숫자 검증 → ②글 → ③클러스터+링크허브 번호 → ④카드 데이터 → ⑤테스트·빌드
   → ⑥카드 이미지 → ⑦OG → ⑧커밋·푸시·배포 대기 → ⑨큐 → ⑩스레드·인스타
```

**절대 어기면 안 되는 두 지점**

- **번호(③)는 카드(④)보다 먼저.** 카드의 `cta.refNo` 가 가리킬 대상이 먼저 있어야 한다. 거꾸로 하면 `npm test` 가 떨어지거나, 더 나쁘게는 없는 번호를 가리키는 카드가 나간다.
- **배포 완료(⑧)는 게시(⑩)보다 먼저.** 스레드·인스타는 이미지를 공개 URL 에서 직접 받아간다. 배포가 끝나기 전에 게시하면 404 를 받는다.

## ① 주제를 고른다 — 무에서 고르지 않는다

`docs/keyword-research.md` 가 v1~v4에서 이미 3축을 데이터로 확정해 놨다. 주제 선정은 그 위에서 **세 필터의 교집합**을 찾는 일이다.

### 필터 1 — 검증된 클러스터 안쪽에서만

`src/data/clusters.ts` 의 3축(종합소득세·원천징수 / 부가가치세 / 노후·연금)을 벗어나지 않는다. 새 축은 SERP 문서 총량을 직접 확인한 뒤에만 연다. 부동산 양도세 롱테일이 2차 후보로 남아 있으나 **미확인** 상태다.

### 필터 2 — CPC·경쟁

- **head 계산기는 피한다.** 퇴직금계산기는 월 29만 검색인데 입찰가 ₩17 — 볼륨만 크고 돈이 안 된다.
- **설명 콘텐츠가 수익 엔진이다.** 종소세 세율·신고대상·인적공제는 Google 5,000 + CPC ₩1,300~1,700.
- 목표대는 CPC ₩1,300 이상 + 경쟁 '낮음'.

### 필터 3 — 캘린더 타이밍

1월 부가세 확정신고 / 1~2월 연말정산 / 5월 종소세 / 7월 부가세 예정신고. **신고철 3~4주 전**에 그 주제를 올린다.

### 지금 비어 있는 칸

`docs/keyword-research.md` v4 인사이트 지도와 대조한 결과:

| v4 인사이트 | 글 | 상태 |
|---|---|---|
| 브릿지: 3.3%는 예납일 뿐 | 3.3%는 종합소득세에서 정산됩니다 | ✔ |
| 반전: 추가납부 가능 | 2026년 종합소득세 세율 구간 | ✔ |
| 절세 레버: 경비율 | 2026년 단순경비율 vs 기준경비율 | ✔ |
| 실수: 여러 곳 합산신고 | — | **빈칸** · CPC ₩1,468 |
| 리스크: 미신고 가산세 | — | 보류(요율 검증 불가) |
| 절세: 인적공제 | — | **빈칸** · GKP 5,000 |

**다음 글 1순위는 인적공제.** 볼륨 5,000, 클러스터 안쪽, 5월 종소세와 타이밍이 맞는다. 2순위는 합산신고.

### 후보를 새로 팔 때 (지도가 소진되면)

1. `discover_keywords` 로 시드 확장 (검색량은 안 나오고 파생어만)
2. 절대량 교차검증 — `keywords/naver-searchad-2026-08-06.json` 에 있으면 그걸 쓰고, 없으면 `.env` 의 `NAVER_SEARCHAD_*` 키로 키워드도구에서 새로 뽑는다
3. SERP 경쟁 확인 — 네이버 `search_webkr` 문서 총량. **10만 대 = 얕음**(3.3% 계산기가 18.9만이었다), **100만 대 = 혼잡**
4. 채택하면 `docs/keyword-research.md` 에 v5로 **append**. 덮어쓰지 않는다 — 판단 이력 자체가 근거다

## ②로 넘어가기 전에 — 매체를 둘로 나눈다

### 발견용 (뭐가 바뀌었나 · 언제 써야 하나) — 인용하지 않는다

- 기획재정부·국세청 보도자료 — 세법개정 일정의 1차 신호
- 국민연금공단 공지 — 요율·기준소득월액 변경
- 네이버 뉴스 검색 — "무슨 일이 있었는지" 파악용. **뉴스의 숫자는 절대 그대로 옮기지 않는다.** 재가공본을 옮기면 오보를 그대로 옮기게 된다
- 네이버 데이터랩 / SearchAd — 수요·계절성 신호

### 검증용 (글에 쓰는 숫자) — 여기서만 가져온다

- **국가법령정보센터 법령 원문** (최우선 — 시행일까지 확인된다)
- **국세청** 세법 안내·「세법개정 후속 시행령」
- **국민연금공단** 공식 안내

발견에서 검증으로 넘어갈 때 **반드시 원문을 다시 연다.** 보도자료에서 본 숫자라도 법령·기관 페이지에서 재확인한 것만 `src/rates/*.json` 에 들어간다 — `sources`(URL) + `verifiedOn` 필수.

**원문에서 확인 못 한 숫자는 글에 쓰지 않는다.** 가산세 항목이 위 표에서 빈칸인 이유가 이것이다.

### 저작권 선

- 정부 보도자료의 **숫자와 문장**은 출처를 달아 쓴다
- 경쟁 블로그 캡처·민간 기업 보도자료 사진은 쓰지 않는다. 공공누리는 해당 기관이 권리를 가진 저작물에만 적용되고, 보도자료 안의 사진은 제3자 권리인 경우가 흔하다
- **출처 표기는 라이선스의 조건이지 라이선스의 대체물이 아니다**

### 연간 리듬

세법개정안 발표(7월 말) → 국회 통과(12월) → 시행령 확정(1~2월). 개정안 단계에서는 **"확정 아님"을 명시**하고, 통과 후에 숫자를 확정 반영한다.

## ② 글을 먼저 쓴다

`src/pages/guide/<slug>/index.astro`

카드뉴스는 글의 요약이지 반대가 아니다. 인스타에 못 담는 예외·조건·계산 과정이 글의 존재 이유다.

- 금액은 **손으로 적지 않고** `src/lib/*.ts` 계산 함수로 뽑는다 (`pension-reform.ts` 의 `rateSchedule()` 처럼)
- 독자는 직장인·사장님·자영업자·프리랜서 전부 — 프리랜서 전용 어휘로 좁히지 않는다

## ③ 클러스터 등록 + 링크허브 번호 배정

`src/data/clusters.ts`
- 해당 클러스터 `links` 에 추가 (`kind: "guide"`, `icon`)
- `recent` 맨 앞에 href → 홈·`nextReads()` 자동 반영
- **연도에 따라 숫자가 바뀌는 글이면 `year: 2026`** 을 넣는다 (아래 "매년 1월" 참조)

`src/data/linkhub.ts`
- `nextNo()` 가 주는 다음 번호로 한 줄. 해당 `hubGroups` 에도 넣는다
- **번호는 재사용·재정렬 금지.** 이미 나간 캡션이 그 번호를 가리키고 있다. 글을 내려도 번호는 비워 둔다
- 라벨은 **30자 이내**, 연도는 붙이지 않는다 (허브는 번호를 찾는 색인이다)

## ④ 카드 세트

`src/data/cards.ts` 의 `cardSets`

- 카드 4~6장, `kind: list | table | note | cta`
- 마지막 장은 `cta` 이고 `refNo` 에 ③의 번호
- 강조는 `[[형광펜]]` / `{{경고}}`
- 카드 금액은 `cards.test.ts` 가 `compute()`·rates JSON 과 대조한다

## ⑨ 큐 글

`social/queue/NNN-<slug>.md`

```markdown
---
images:
  - /cards/<slug>/1.jpg
  - /cards/<slug>/2.jpg
reply: 한 줄 요약. 프로필 링크에서 N번 글입니다 → jupocket.com

본문 첫 줄이 후킹. 링크는 절대 넣지 않는다.
```

- 인스타는 캡션 URL 이 클릭되지 않으므로 같은 `reply:` 가 캡션 끝 "프로필 링크에서 N번 글" 안내가 된다 — 양쪽이 한 파일로 해결된다
- 본문 450자 경고 / 500자 상한, 캡션 2200자 상한

## 발행 구조 — 월간 테마 + 계측

### 한 편에서 몇 개가 나오나

**10개는 무리다.** 억지로 쪼개면 카드가 얇아지는데, 인스타에서 확인한 우리 강점이 정확히 그 반대다 — 조밀한 표·번호 목록·출처 표기. 쪼개서 늘리면 이기고 있던 걸 버린다.

- 깊은 글 1편 = **각도 3~4개**
- 월 6~12 게시물 = **깊은 글 2~3편 × 각도 3~4**

각 각도는 ④~⑥·⑨~⑩만 반복한다 (글·번호는 그대로).
예) 국민연금 글 → "얼마 더 내나" / "직장인 vs 지역가입자" / "언제부터"

### 월간 테마

한 달을 한 주제로 묶고 캘린더에 건다. 그 달의 글·카드가 전부 같은 축이라 서로를 밀어준다.

| 시기 | 테마 |
|---|---|
| 1월 | 부가세 확정신고 + 연말정산 |
| 5월 | **종합소득세** (최대 성수기 — 가장 두껍게) |
| 7월 | 부가세 예정신고 + 세법개정안(확정 아님 명시) |
| 그 외 | 노후·연금, 평생글로 메운다 |

### 재활용은 "재업로드"가 아니라 "리믹스"

같은 이미지를 다시 올리면 도달이 죽는다. 반응 좋았던 각도를 다시 낼 때는:
- **30일 이상** 간격
- 후킹 문장과 카드 형식을 바꾼다 (표 → 번호 목록, 질문형 → 단언형)
- 숫자가 바뀌었으면 ⑥부터 다시

### 계측

```bash
npm run stats           # 수집해서 social/stats.json 에 쌓고 표로 보여준다
npm run stats -- --show # 수집하지 않고 쌓인 것만 본다
```

인스타는 며칠에 걸쳐 오른다. 게시 직후 한 번만 보면 안 되고, **48시간·7일 시점**에 다시 돌린다. 덮어쓰지 않고 쌓으므로 증가 곡선 자체가 신호가 된다.

**1개월차는 측정 구간이다.** 월간 테마로 6~12건을 내고 찍기만 한다. 4주 데이터가 모이면 그때 "반응 좋은 각도"가 정의되고, 2개월차부터 그걸 리믹스 축으로 삼는다.

## 검색·AI 검색에 걸리게 하는 것 (자동으로 되는 것들)

글·카드를 규칙대로 넣으면 아래는 따라온다. **따로 손댈 필요 없지만, 왜 그런지는
알아야 망가뜨리지 않는다.**

- **카드 내용이 페이지에 글자로 실린다** — `src/lib/card-text.ts` 가 `cards.ts`
  에서 alt·전문·요약을 뽑는다. 카드뉴스 페이지는 JPEG 가 전부라 그림 안 내용은
  기계가 못 읽는다. `cards.ts` 를 제대로 채우면 그대로 검색 대상이 된다
- **구조화 데이터** — 글은 `Article`(`dateModified` = 각 글의 `updated`,
  `citation` = 국세청·국민연금공단·국가법령정보센터), 카드 세트는
  `ImageGallery` + 장마다 `ImageObject`
- **사이트맵 `lastmod`** — `astro.config.mjs` 가 빌드 때 각 글의 `updated` 를
  읽는다. **날짜를 지어내지 않는다.** 모르는 페이지는 비워 둔다 — 오늘로 채우면
  배포할 때마다 전부 "오늘 바뀜"이 되어 신호가 죽는다
- **`public/robots.txt`** — GPTBot·OAI-SearchBot·ClaudeBot·PerplexityBot·
  Google-Extended·Applebot-Extended·CCBot 을 명시적으로 허용한다. 막아두면 AI
  답변에 우리 글이 아니라 **우리 글을 베낀 곳**이 인용된다

**그래서 ②에서 출처를 원문으로 다는 일이 두 배로 중요하다.** AI 답변은 근거가
분명한 문서를 고른다 — 숫자 옆의 "출처 국세청"이 사람용 면피가 아니라 인용되는
이유가 된다.

## 운영상 기억할 것

- **토큰은 양쪽 60일**이고 게시할 때마다 자동 연장된다 → **60일 넘게 안 올리면 죽는다.** 죽으면 `npm run social:setup` / `npm run ig:setup`
- **인스타는 이미지 필수** → 텍스트 전용 큐 글은 `ig:post` 가 자동으로 건너뛴다
- **제목·클러스터를 바꾸면 `npm run og` 재실행.** 카드 내용을 바꾸면 ⑥부터 다시

## 매년 1월의 숙제

2027년 1월에 "2026년 …"이 그대로 떠 있으면 최신 신호가 정확히 반대로 작동한다. 그래서 연도 올리기는 선택이 아니라 고정 작업이고, **순서가 있다**:

1. `src/rates/*.json` 을 원문으로 재검증하고 `verifiedOn` 갱신
2. 그 **뒤에** `clusters.ts` 의 `year: 2027` 로 올린다
3. `npm test` → `npm run og`(제목이 바뀌었으므로 OG 재굽기) → 카드에 연도가 적혀 있으면 ⑥부터 다시

**숫자를 확인하지 않고 연도만 올리는 것은 가짜 최신화다. 하지 않는다.**

연도를 붙이는 글과 안 붙이는 글은 `clusters.ts` 의 `year` 필드가 결정한다. 계산기(항상 최신)와 평생글(`IRP란?` 같은 구조 설명)에는 붙이지 않는다.
