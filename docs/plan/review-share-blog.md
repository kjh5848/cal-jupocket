# 공유할 수 있는 블로그 — 조사와 제안 (2026-11-22)

사용자 말: "좋았다면 후기를 남기고 리뷰 남길 수 있게끔 하고 공유할 수 있는 그런 블로그도 한번 하면 좋을 것 같은데."
코드는 고치지 않았다. 아래는 저장소를 직접 열어 확인한 사실과, 확인하지 못해 추측으로 표시한 것을 나눠 쓴 제안이다.
기준 스킬 `mk-content:content-strategy`, `mk-search:site-architecture`, `mk-search:ai-seo` 는 모두 불러서 따랐다.

## 0. 한 문단 결론

- "블로그"는 (나) **전세 주제 글 묶음**으로 연다. 이유 하나가 결정적이다. `/jeonse-chat/` 는 noindex 이고 사이트맵에서도 빠져 있어(`src/pages/jeonse-chat/index.astro` 22행, `astro.config.mjs`), 검색엔진과 AI 답변이 읽고 인용할 수 있는 전세 표면은 **정적 글뿐**이다. 그런데 전세가 중심인 글은 지금 2편이다.
- (가) 후기·리뷰는 **공개 벽이 아니라 비공개 수집**으로 시작한다. 세션 449에 공개 후기 벽은 비어 보이고, 지어서 채우면 표시광고법 문제다.
- (다) 네이버 블로그는 글이 4편 이상 쌓인 뒤 "다른 각도 요약 + 원문 링크"로만 연다. 지금은 보류.
- 새 주소 접두사(`/blog/`, `/jeonse/`)를 만들지 않고 `/guide/{slug}/` 에 둔다.

키워드 데이터가 없으므로 유입 기대는 모두 **추측**이다. 숫자로 예측하지 않고, 아래 "먼저 볼 지표"로 4주 뒤 판단한다.

|---|---|---|---|

## 3. 실제 후기가 없을 때 정직하게 채우는 법

### 쓸 수 있는 재료

| 종류 | 무엇 | 꼭 지킬 것 |
|---|---|---|
| A. 예상 질문 Q&A 글 | `hug-answers.json` 의 질문·답을 글로 펴기 | "도우미에 준비해 둔 자주 나오는 질문"이라고 쓴다. **"사용자가 실제로 물은"이라고 쓰지 않는다** — 58개는 예상 질문이다(로그 아님) |
| B. 공식 자료 상황별 글 | KB·상황 안내·특약 조사(표준계약서 인쇄 문구) | 출처 이름·링크·확인일을 글 안에. 숫자는 `src/rates/*.json` 에서 템플릿으로 |
| C. 가상 사례 | 계산기에 넣을 가상 입력 → 결과 | **글 맨 위에** "가상 사례"를 표시한다. 입력은 가상이어도 결과는 사이트 계산 코드가 낸 값이어야 한다 |
| D. 실제 질문 기반 글 | 월요일 `docs/chat-log.md` 가 쌓인 뒤, 가린(마스킹) 질문 상위 N개 | 로그가 있을 때만 "실제 질문"이라 쓴다. 개인정보는 관리자 화면의 가림 규칙을 재사용. 표본 수를 같이 적는다 |
| E. 유튜브 사례 유형 | 114건 조사에서 나온 "막히는 유형"(잔금 다음 날 전입, 임차권등기 전 이사 등) | **유형으로만** 쓴다. JU포켓 사용자 이야기처럼 쓰지 않는다. 영상 속 숫자(5%·12%·77.5% 등)는 확인된 값이 아니므로 안 쓴다 |

### 하면 안 되는 것

1. 지어낸 후기·별점·"N명이 이용" 같은 숫자. 후기 문장을 다듬어 고치는 것도 포함.
2. 가상 사례를 표시 없이, 또는 본문 중간·아래에만 표시.
3. 유튜브에서 본 사연을 JU포켓 이용자 사연으로 옮기기.
4. 결과를 보장하는 말("가입하면 안전", "덕분에 돌려받았어요").
5. 집주인·중개사·건물 실명이 나오는 사기 이야기(명예훼손 위험).
6. 자기 서비스에 `Review`·`AggregateRating` 구조화 데이터.
7. 혜택(쿠폰·선물)을 주고 받은 후기를 표시 없이 게시.
8. 다른 목적으로 받은 입력(도우미 질문)을 동의 없이 후기로 공개.
9. `hug-answers.json` 의 답을 **글에 그대로 복사**. 41/58 개 답이 숫자를 직접 담고 있다(예: 갱신거절 답의 "2개월"). 저장소 규칙(숫자는 `rates` 근거)을 따라 `hug-jeonse-checklist` 처럼 `${D.renewalNoticeToMonths}` 꼴 템플릿으로 렌더한다.

### (가)를 작게 여는 법 — 비공개 먼저

- 글 끝·도우미 답 뒤에 "도움이 됐나요? 예/아니오 + 한 줄(선택)" 한 쌍. 공개하지 않고 관리자 화면에만 보인다. 이 숫자가 곧 어떤 글·답을 고칠지 알려 준다.
- 공개는 승인된 항목이 10건 정도(제안값) 쌓인 뒤에, 작성자 동의·가림·검수를 거쳐서만. 그 전엔 공개 후기 칸을 만들지 않는다.
- 사용자의 말 "좋았다면 후기"는 이 방식으로 들어준다. 네이버 쪽 "후기"는 사용자가 알아서 블로그에 쓰는 것이라 우리가 만들 수 없다.

## 4. 전세 글 묶음 설계 (나)

### 주소 구조

```
/guide/jeonse-contract-to-expiry/     허브 — 계약 전·잔금·거주·만기·사고, 날짜와 순서의 타임라인
├── /guide/jeonse-special-clauses/    스포크
├── /guide/jeonse-renewal-notice/     스포크
├── ... (아래 표)
└── 기존: /guide/hug-jeonse-checklist/ (일정 도구), /guide/hug-jeonse-guarantee-calculator/ (계산)
도우미: /jeonse-chat/ (noindex 유지, 글 끝에서 들어가는 입구)
```

- `/guide/` 아래에 둔다. RSS(`guideMeta`)·사이트맵 lastmod(`guideDates`)·OG·CONTENT.md 열 단계가 모두 `/guide/` 에 걸려 있어, 새 접두사는 이 파이프를 둘로 가른다. `/blog/` 도 `/jeonse/` 도 만들지 않는다.
- 허브는 `/guide/brokerage-fee/` 처럼 **내용 있는 글**이어야 한다(링크 목록만 있는 페이지는 안 된다). 허브의 척추는 조사 결과 "돈을 잃는 지점은 계산이 아니라 날짜와 순서"(`2026-11-15-jeonse-youtube-cases.md`)를 시간 순 표로 옮긴 것. 스포크가 3~4편 쌓인 뒤에 만든다(스킬은 허브 먼저를 권하나, 지금은 스포크가 허브의 재료다).
- 클러스터: `clusters.ts` 의 `money` 클러스터에 이미 두 전세 글이 붙어 있다. 전세 글 묶음은 별도 축이 아니라 "집·차"(또는 money) 안의 하위 줄기로 둔다. 새 축은 SERP 확인 뒤에만 연다는 CONTENT.md 필터 1을 따른다 — 아래 8절 확인 못한 것 참고.

### 첫 5~8편 후보

"겨냥하는 질문"과 "근거"는 KB·답 번호로 이미 닫혀 있다. "정보 이득(내가 더하는 것)"은 **SERP 를 열어 보지 않은 가설**이다. 쓰기 전에 상위 결과를 읽고 한 문장을 확인한다(스킬의 information-gain gate).

### 도우미로 잇는 법

- 글 → 도우미: 글 끝 버튼. 도우미가 특정 답을 바로 여는 링크(`?q=`)는 현재 코드에서 **찾지 못했다**(grep 결과 없음). 이것이 있으면 글마다 "이 질문 이어서 묻기"를 걸 수 있다. 작은 개발 한 건으로 따로 적어 둔다(확인 필요).
- 도우미 → 글: 답 뒤 버튼 줄에 해당 글 링크. 도우미가 noindex 라 이 방향은 검색에는 영향이 없고 체류·신뢰용이다.
- "도움이 됐나요"(3절)를 글과 도우미 답 양쪽에 붙이면 같은 질문이 어느 쪽에서 약한지 보인다.

### 공유 버튼·OG

- 공유 버튼은 이미 있다. 새로 만들 것은 없다. 카카오 리치 공유는 SDK 가 필요해 일부러 뺀 것이라 그대로 둔다(네이티브 공유가 모바일에서 카톡을 커버).
- `ShareButtons` 가 GA4 이벤트를 보내는지는 열어 본 범위(주석·클릭 처리)에서 **이벤트 전송 코드를 못 찾았다**. 보내지 않는다면 공유 횟수를 못 센다 — 확인 필요.
- **글마다 OG 이미지가 곧 공유 미리보기**다. CONTENT.md 7단계에서 만들지 않으면 `home.png` 로 떨어져 공유 카드가 모두 똑같아진다. 질문형 제목을 그대로 큰 글씨로 얹은 카드가 적합하다고 본다(제안).
- 공유가 일어나는 곳은 카톡 단체방과 앱 안 브라우저이므로(추측) 링크를 열었을 때 첫 화면이 답이어야 한다.

## 5. 검색·AI 답변 유입에 어떻게 기여하나

| | 구글 | 네이버 | AI 답변(ChatGPT·Perplexity·Gemini, 네이버 AI 브리핑) |
|---|---|---|---|
| 글이 하는 일 | 롱폼 질문 하나당 한 URL. 허브-스포크 내부 링크 | 사이트 글은 웹문서 쪽. 블로그·카페·지식iN 아래에 놓일 수 있음 | 40~60단어 답 블록, 질문형 H2, 출처 인용 |
| 이미 있는 장치 | Article·FAQPage JSON-LD, lastmod | RSS(`rss.xml`) | `llms.txt`, 작성자 Organization |
| 해야 할 것 | 새 글을 사이트맵·내부 링크(허브 + `linkhub`)에 | 서치어드바이저 RSS·수집 요청 상태 확인(미확인), 글 4편 이상 후 블로그 연동 | 검색용 AI 봇 허용 여부 확인(아래) |

- **FAQ 구조**: `faq` prop 을 써서 글마다 질문·답 2~4쌍을 JSON-LD 와 본문에 같이 낸다. 구글은 FAQ 리치 결과를 정부·보건 사이트 위주로 제한하므로(레이아웃 주석) 구글 스니펫 효과는 기대하지 않고, AI 요약이 질문-답 짝을 읽는 효과만 본다.
- **출처 표기**: 법령 조문, HUG 안내 페이지, 표준계약서에 이름·링크·확인일을 쓴다. AI 엔진이 인용하기 쉬운 것은 통계·출처 달린 문장이라는 연구(Princeton GEO 2023, 인용 +40% / 통계 +37%)가 있으나 외부 연구이고 이 사이트에서 검증한 것은 아니다.
- **봇 접근**: `robots.txt` 주석상 학습용 AI 봇(GPTBot·ClaudeBot·Google-Extended 등)은 Cloudflare 관리형 블록으로 막혀 있다. 학습 차단과 검색 인용은 별개이지만, OAI-SearchBot·PerplexityBot·Claude-SearchBot 이 막혔는지는 이 저장소 파일로는 알 수 없다. AI 16세션이 있어 일부는 통과하는 것으로 보인다. **Cloudflare 대시보드에서 검색용 봇을 확인**하는 일이 글 8편보다 먼저다.
- **지표**: GA4 의 AI 출처 세션, Search Console 에서 새 URL 의 노출(4주 뒤), 도우미 "도움이 됐나요" 비율.
- 정직한 한계: 조회 데이터가 작아(스레드 전세 13편이 70 조회) 어떤 글이 이긴다고 지금 말할 수 없다.

## 6. 네이버 블로그 등 바깥 채널의 득실

| 득 | 실 |

## 8. 확인하지 못한 것

- 전세 키워드의 월 검색량·경쟁·상위 결과(SERP). `keywords/` 에 전세 CSV 가 없고 `discover_keywords.py` 도 돌리지 않았다. 4절의 "더하는 것"과 2절의 유입 기대는 가설·추측이다. **새 축은 SERP 확인 뒤에만 연다**는 CONTENT.md 필터 1을 이번에는 만족시키지 못했다 — 3편 쓰기 전에 시드(갱신거절 통보, 임차권등기, 공시송달 전세, 전세 특약, 보증 거절)로 확인한다.
- GA4 숫자(449 등) 전부와 스레드 70 조회는 의뢰서 값이다.
- 네이버 Yeti 가 `robots.txt` 에서 허용되는지, 서치어드바이저에 RSS 를 제출했는지.
- Cloudflare 관리형 블록에서 OAI-SearchBot·PerplexityBot·Claude-SearchBot 이 막혔는지.
- `ShareButtons` 가 GA4 이벤트를 보내는지(전송 코드를 못 찾음), 도우미가 특정 질문을 바로 여는 링크를 받는지(못 찾음).
- 질문·평가 저장소(워커 쪽 KV·D1 등)에 후기 칸을 넣을 수 있는지, 관리자 화면에 어떻게 붙일지.
- 표시광고법·정보통신망법·개인정보법의 구체 조문은 일반 지식이며 law.go.kr 에서 열어 확인하지 않았다. 후기 공개 전에 확인한다.
- 다른 전세 언급 글(dsr, 연금 등)은 일부 제목만 열었다.

## PM 에게 넘길 권고

1. "블로그"는 (나) 전세 주제 `/guide/` 글 묶음으로 간다. 도우미가 noindex 라 검색·AI 가 읽을 전세 표면은 글뿐이고 지금 2편이다.
2. 첫 판은 A안 — 특약 → 갱신거절 날짜 → 보증금 안 돌려줄 때 3편. 숫자는 `rates` 템플릿으로, `hug-answers` 문장 복붙 금지. 쓰기 전에 전세 키워드·SERP 를 확인한다.
3. 후기는 비공개 "도움이 됐나요"로만 받고, 공개는 승인된 항목 약 10건 뒤. 지어낸 후기·표시 없는 가상 사례·Review 마크업은 하지 않는다.
4. 공유 버튼·FAQ 구조는 이미 있다. 새로 할 것은 글마다 OG 와 Cloudflare 에서 검색용 AI 봇 허용 확인.
5. 네이버 블로그는 글 4편 이상 뒤 "다른 각도 요약 + 원문 링크"로만, 지금은 보류.
