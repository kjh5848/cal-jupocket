## 지켜야 할 것 (매 회차)

- **베끼지 않는다.** roberin 은 입력 항목·선택지·결과 항목·계산 방향만 본다. 화면 캡처·문구·코드·디자인·고유 이름은 가져오지 않는다. 결과 숫자를 우리 정답으로 쓰지 않는다 — 비교용일 뿐.
- **숫자는 원문.** 세율·한도·요율은 law.go.kr(법·시행령·고시)·국세청·공단 원문으로 확인해 `src/rates/*.json` 에 `sources`·`verifiedOn` 과 함께. 확인 못 하면 그 도구는 **보류**(메모에 막힌 이유)로 두고 다음 줄로 넘어간다 — 멈추지 않는다.
- **글과 같이 간다.** 법·제도 도구는 지금처럼 3편 시리즈(허브 + 계산기 글 + 관련 질문 글)로 낸다(`jupocket-daily`·`keep-writing-no-asking` 규칙). 범용 도구는 `/tools/<slug>/` 한 페이지.
- 링크허브 번호는 `nextNo()` 로만. 재사용·재정렬 금지.
- 테스트(`set -o pipefail; npm test > out.txt`)·빌드 통과 전에는 커밋하지 않는다. `git add` 는 파일을 명시, `social/*.json`·`.claude/launch.json` 제외.
- 막히면 추측하지 않는다. 하루 거르는 게 틀린 숫자보다 낫다.

## 한 회차 (약 1묶음 = 도구 1~3개)

### 0. 잠금·작업 트리 확인 (먼저, 매번)
- [ ] 저장소 루트에 `.routine-lock` 파일이 있으면 **아무것도 하지 않고 끝낸다**(다른 세션이 디자인 적용 등 큰 작업 중). 파일 첫 줄에 이유가 있다.
- [ ] `git status --short` 에서 `social/*.json`·`.claude/launch.json` 말고 바뀐 파일이 있으면 끝낸다(남의 작업을 덮지 않는다).
- [ ] 시작하면 `.routine-lock` 을 만들고(`routine <시각>`), 끝날 때(성공·실패 모두) 지운다. 30분 안에 못 끝내면 다음 회차는 0단계에서 자동으로 건너뛴다.

### 1. 상태 보기
- [ ] `git pull` 후 `docs/tool-backlog.md` 맨 위 "현재:" 줄과 `진행 중` 행을 본다. `진행 중` 이 있으면 그것부터 끝낸다.
- [ ] 리브랜딩 기반 계획의 미완료 Task 가 있으면 **이번 회차에 그 Task 하나를 먼저** 한다(도구가 늘기 전에 틀이 서야 이전 비용이 작다). 기반이 끝났으면 2로.

### 2. 고르기
- [ ] 표는 법·제도 영역(세금·급여·연금·집·상속·돈)이 위에 있다. 위에서부터 `할 일` 을 고르되, 같은 묶음(예: 대출계산기·대출이자·중도상환수수료)은 한 회차에 같이.
- [ ] 우선순위는 v54 검색량 순: 퇴직금 → 대출·대출이자 → 예적금 이자 → 시급 → DSR → 중개보수 → 통상임금·야근수당 → 일용직 4대보험 → 하루 실수령액 → 그다음 범용(퍼센트·날짜·D-day·만 나이·평수).
- [ ] 고른 행을 `진행 중` 으로 바꾼다.

### 3. roberin 도구 관찰 (기능만)
- [ ] 내장 브라우저로 그 roberin 주소를 열고 기록한다 — 입력 항목과 순서, 선택지, 계산 방향(정방향·역산), 결과 항목, 예시 입력 1개에 대한 결과값.
- [ ] 기록은 `docs/calc-benchmark.md` 에 한 행: 우리 주소(예정) · roberin 주소 · 입력 비교 · 결과 항목 비교 · 예시 결과값 · 우리가 더할 것/뺄 것.

### 4. 판정
- [ ] **가져온다**: 우리 영역이고 원문으로 닫히는 것, 또는 범용으로 검색 수요가 있는 것.
- [ ] **있음으로 합친다**: 우리 기존 도구에 입력·결과 항목 하나 더하면 되는 것(예: 3.3% 계산기에 부가세 포함 방향) → 기존 도구를 고치고 행은 `있음` + 메모.
- [ ] **제외**: 우리 원칙과 안 맞는 것(근거 없는 '부자 시계' 류, 의료 판단이 필요한 건강 도구, 다른 나라 세법 — 나라별 단계 전) → 메모에 이유.

### 5. 로직 비교 (있음 도구 + 새로 만든 도구 모두)
- [ ] 같은 입력 3개(작은 값·보통·경계값)를 roberin 과 우리 도구에 넣어 결과를 표로 비교한다.
- [ ] 다르면 **원문으로 누가 맞는지** 판정한다. 우리가 틀렸으면 그 회차의 첫 커밋으로 고친다(`fix:`), roberin 이 다르면 메모에 이유(예: 단수 처리·기준연도 차이)만 남긴다.
- [ ] 비교 결과는 `docs/calc-benchmark.md` 행에.

### 5.5 나라별 확인 — 이 도구를 다른 나라도 같은 식으로 쓰나
대상 나라(고정 목록): 한국(기본) · 미국 · 캐나다 · 영국 · 독일 · 프랑스 · 스페인 · 일본 · 중국 · 대만 · 홍콩 · 싱가포르 · 호주 · 인도네시아.
- [ ] `docs/country-matrix.md` 에 이 도구 한 행: 나라마다 **같음 / 단위·표기만 다름 / 제도가 다름 / 없음** 과 근거(공식 출처 주소).
- [ ] **범용 도구**(단위·날짜·건강·텍스트 등): 나라마다 다른 것은 단위·표기·관습이다 — 예: 평 ↔ ㎡ ↔ ft², kg ↔ lb, 섭씨 ↔ 화씨, 주 시작 요일, 나이 세는 법, 날짜 표기, BMI 분류 기준(WHO 와 아시아·태평양 기준 — 출처 확인 뒤). 같은 페이지에 **나라·단위 선택**을 두고 계산을 바꾼다. 기준값이 나라마다 다르면 출처를 rates 에.
- [ ] **법·제도 도구**(세금·급여·연금·부동산): 나라마다 법이 다르다. 그 나라 정부 공식 원문(예: 미국 IRS, 일본 国税庁·e-Gov, 영국 GOV.UK, 캐나다 CRA, 독일 BMF)으로 확인된 나라만 행에 '검증됨' — 실제 페이지는 그 나라 언어판(`/ja/` 등, 설계 2절: 한국 → 일본 순)이 열린 뒤 만든다. 그 전까지는 매트릭스와 rates 초안(`src/rates/<나라>/<주제>-<연도>.json`, 페이지에서 안 씀)까지만.
- [ ] 원문을 못 찾은 나라는 '미확인' — 추측해서 '같음'이라 적지 않는다.

### 6. 만들기
