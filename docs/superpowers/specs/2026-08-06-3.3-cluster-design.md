# cal.jupocket.com — 프리랜서 3.3% 클러스터 설계

작성 2026-08-06 · 상태: 승인 대기(사용자 검토)

## 0. 배경과 목표

한국형 계산기 사이트를 **SERP 틈 니치** 전략으로 만든다. 검색량 크고 경쟁 센
head 계산기(퇴직금 291K·시급 187K·부가세 97K 등)는 네이버·토스·홈택스가 점령해
신생 사이트가 못 이긴다. 대신 **경쟁 약한 구체 니치**를 깊이로 공략한다.

키워드 조사(`docs/keyword-research.md`)로 확정한 1차 클러스터:
**프리랜서 원천징수 3.3% / 종합소득세 환급.**
- `3.3%계산기` 24,330/월, 경쟁 낮음, SERP 약함(소규모 사이트만 랭킹 — 검증됨)
- 원천세 2.9K·원천징수 2.5K·종합소득세 환급 연계
- 5월 종소세 신고철 재방문성, 프리랜서 인구 증가

목표: 이 클러스터로 검색 유입 → AdSense 수익. 보험 사이트와 같은 **정적·검증
우선** 규율을 유지한다.

## 1. MVP 범위 (3종 계산기)

서로 링크되는 한 주제 클러스터. 이 3종만. (부동산 양도세 클러스터는 이 클러스터
검증 후 2차로.)

1. **프리랜서 3.3% 원천징수 계산기** (플래그십)
   - 계약금액 → 실수령액·원천징수액
   - 실수령액 → 계약금액 역산
2. **원천징수 계산기** — 사업소득 3.3% + 기타소득 8.8%(강연료·원고료 등 필요경비
   60% 유형) 선택
3. **종합소득세 환급 예상 계산기** — 3.3% 뗀 프리랜서의 5월 예상 환급/추가납부

## 1.5 설명 콘텐츠(explainer) 층 — "각 구간이 뭔지" 해설

많은 이용자가 계산 결과의 구성(3.3%가 뭔지, 누진세율 구간, 경비율, 인적공제)을
모른다. 계산기 옆에 그 개념을 해설하는 콘텐츠를 붙인다. **단순 계산기만 있는 경쟁
사이트를 깊이로 이기는 핵심** — 보험 사이트가 얕은 리드젠을 깊이로 이긴 것과 같은
전략. 계산기(값) + 해설(왜/어떻게)이 상호 링크되어 클러스터 토픽 권위를 만든다.

두 층으로 낸다:
1. **인라인 설명 블록** — 계산기 페이지 내 접이식. 결과가 왜 이 값인지 즉석 해설.
   이탈 없이 교육. 그 계산기가 쓰는 개념만.
2. **독립 해설 글(SEO)** — 검색 수요 있는 개념은 별도 URL 글. 계산기 ↔ 글 상호링크
   → 롱테일 유입 + 토픽 권위.

해설 주제(3.3% 클러스터):
- 3.3% 구성 (소득세 3% + 지방소득세 0.3%)
- 사업소득 3.3% vs 기타소득 8.8% 차이
- 3.3% 환급이 나오는 구조 (기납부 vs 결정세액)
- 종합소득세 누진세율 **구간** (2026, 과표 구간별)
- 단순경비율 vs 기준경비율
- 인적공제 (본인·부양가족)
- 종소세 신고 대상·기간(5월)

원칙:
- 독립 글은 **보험과 같은 키워드/SERP 규율** — 개념 키워드("종합소득세 구간",
  "단순경비율이란", "기타소득 8.8%" 등)의 수요·경쟁을 네이버 키워드도구/SERP로
  확인 후 채택. 무작정 다 쓰지 않는다.
- 세율·구간 숫자는 §3의 국세청 대조 `rates` 데이터를 **계산기와 글이 공유** — 값이
  한 곳에서 나와 불일치가 없다.
- 정확성 고지 동일 적용.

MVP 반영: 계산기 3종 + **각 계산기의 인라인 설명 블록**. 독립 해설 글은 검증된
개념부터 **1~3편**(플래그십 3.3% 관련) 함께 출시. 나머지 개념 글은 후속.

## 2. 계산 로직 (돈 계산 — 정확히 명세)

### 2.1 사업소득 3.3% 원천징수
- 3.3% = 소득세 3% + 지방소득세 0.3%(소득세의 10%)
- 계약금액 C → 원천징수 = round(C × 0.033), 실수령 = C − 원천징수
- 실수령 R → 계약금액 = round(R / 0.967) (역산은 반올림 오차 안내 문구 표시)

### 2.2 기타소득 8.8%
- 필요경비 60% 인정 유형: 과세 40% × 22%(소득세20%+지방세2%) = 총액의 8.8%
- 유형·경비율이 다르면 값이 달라짐을 명시(기본은 60% 경비 유형)

### 2.3 종합소득세 환급 예상 (단순 모델 + 강한 고지)
입력: 연간 사업소득 총수입, 단순경비율(업종 선택 또는 직접입력), 인적공제 인원,
기납부세액(= 총수입 × 3.3%, 자동).
- 필요경비 = 총수입 × 단순경비율
- 소득금액 = 총수입 − 필요경비
- 과세표준 = 소득금액 − 인적공제(본인 150만 + 부양가족 각 150만) [MVP 기본]
- 산출세액 = 과세표준 × 누진세율 − 누진공제 (아래 세율표)
- 결정세액 = 산출세액 − 표준세액공제(7만) [MVP 기본]
- 환급/추납 = 기납부세액 − 결정세액 (양수=환급, 음수=추가납부)
- **가정을 화면에 명시**하고 "예상치, 실제는 홈택스 모두채움 신고로 확정" 고지.
  세액공제·타 소득·건보료 등은 MVP 미반영임을 분명히 한다.

## 3. 세율·상수 = 버전 데이터 (국세청 대조)

세율은 코드가 아니라 `src/rates/2026.json`에 둔다. 매년 갱신 = 데이터 변경.
- 종합소득세 누진세율표(과표 구간·세율·누진공제) — **국세청/홈택스 원문 대조 후 확정**
- 지방소득세율(소득세의 10%), 3.3%/8.8% 상수, 단순경비율(주요 업종)
- 각 값의 출처(국세청 페이지 URL)와 확인일을 `rates/2026.json`에 주석/메타로 남긴다
  (보험의 sources 규율과 동일 정신). **미검증 세율로 발행하지 않는다.**

## 4. 아키텍처

보험 스택 재활용: **Astro + Cloudflare Workers Static Assets**, 계산은 **클라이언트
JS**(서버·DB 없음). 별도 레포(`cal-jupocket`), 배포 `cal.jupocket.com`(서브도메인,
독립 배포).

```
src/
  pages/            계산기별 페이지(3) + index + 정책/소개
  components/       Calculator UI, AdSlot, ClarityHead, 공통 레이아웃
  rates/2026.json   세율·상수(버전)
  lib/              계산 순수함수(입력→결과) + 단위 테스트
```
- **계산 로직은 lib/의 순수함수로 분리** — 입력→출력, 부수효과 없음, 단위 테스트로
  숫자 검증(반올림·경계값). UI와 분리해 테스트·재사용.
- 정적 출력이라 호스팅 잠김 없음(보험과 동일 이점).

## 5. 수익화

- Google AdSense — **기존 계정에 cal.jupocket.com 사이트 추가**(별도 사이트 등록).
- 배치 규율(보험과 동일): **입력 필드 중간·결과 계산 흐름 사이 광고 금지**,
  결과 아래/관련 설명 옆만. 페이지당 3개 이하. 오도성·강제 인터스티셜 없음
  (서브도메인 정책 위반은 루트 jupocket 신뢰도까지 위협).
- Microsoft Clarity(행동 분석) 재사용 가능(별도 프로젝트 ID).

## 5.5 액션 — 결과 산출물 다운로드·공유 (PNG)

계산이 "값만 보고 끝"나지 않게 한다. 결과를 **산출물로 만들어 액션을 유도**한다.
이게 재방문·공유·유입 루프를 만드는 성장 장치다.

- **결과 카드 PNG 다운로드** — 입력값·결과·적용식 요약·고지·`cal.jupocket.com`을
  담은 브랜드 카드를 **클라이언트에서 canvas 로 렌더 → PNG 저장**.
- **공유** — Web Share API(모바일 네이티브 공유) + 링크/텍스트 복사. **공유 PNG 에
  사이트 URL 을 새겨 "공유 → 유입" 루프**를 만든다.
- **복사** — 결과 텍스트 클립보드 복사.
- 전부 **클라이언트, 서버·PII 전송 0**(개인정보 일관). 외부 폰트·무거운 라이브러리
  지양 — canvas 직접 렌더 또는 경량 방식으로 CWV 유지.

**콘텐츠 → 계산기 → 산출물 퍼널:** 설명 콘텐츠(§1.5)는 개념을 읽은 사람을 계산기로
유도(CTA)하고, 계산기는 결과를 PNG 산출물로 내보내 공유하게 한다. 세 층이 한
흐름으로 물린다.

## 6. 정확성·신뢰

- 각 계산 결과에 **적용 식·가정·세율 출처**를 접이식으로 표시.
- "참고용 예상치, 법적 효력 없음, 정확한 건 홈택스/세무사" 고지 상시.
- 돈 계산이므로 반올림 규칙을 명시(원 단위 반올림)하고 테스트로 고정.

## 7. SEO

- 3종이 한 클러스터로 상호 내부링크(플래그십 3.3% 허브).
- 타깃: `3.3%계산기`·`프리랜서 3.3 계산기`·`원천징수 계산기`·`종합소득세 환급
  계산기` 등 검증된 저경쟁 키워드. head(부가세·퇴직금) 안 노림.
- 각 페이지 title/description/canonical, 계산기 구조화 데이터, `llms.txt`(보험처럼).
- 한국 시장이라 유입은 Google + 일부 네이버. 기대치는 Google SEO 기준.

## 8. 세율 갱신 운영

- 연 1회(연말/연초) `rates/<연도>.json` 신규 작성, 국세청 대조 후 교체.
- 5월 종소세철 전 환급 계산기 세율·경비율 재확인.
- 갱신 이력을 커밋으로 남긴다.

## 9. 범위 밖 (YAGNI)

- 부동산 양도세/보유세 클러스터(2차, 별도 spec)
- 실업급여계산기(정부 지배 가능 — SERP 확인 후 별도 판단)
- 로그인·저장·API·뉴스레터. 계산은 전부 클라이언트, 서버 없음.
- head 계산기(퇴직금·시급·부가세 등) 정면 경쟁.

## 10. 확정 사항

1. 1차 클러스터 = 프리랜서 3.3% 원천징수/종소세 환급, MVP 3종
2. **설명 콘텐츠 층** — 인라인 설명 블록 + 독립 해설 글(검증된 개념 1~3편). 계산기와
   `rates` 소스 공유. 콘텐츠 → 계산기 유도(CTA)
3. **결과 산출물** — 결과 카드 PNG 다운로드 + Web Share/복사. 공유 PNG 에 사이트 URL
   → 유입 루프. 전부 클라이언트, PII 전송 0
4. Astro + Cloudflare 정적 + 클라이언트 JS, 별도 레포, cal.jupocket.com
5. 계산 로직은 lib/ 순수함수 + 단위 테스트, 세율은 버전 JSON(국세청 대조)
6. AdSense 기존 계정 + 배치 규율, Clarity 재사용
7. 부동산 클러스터·실업급여·서버 기능은 범위 밖(후속)
