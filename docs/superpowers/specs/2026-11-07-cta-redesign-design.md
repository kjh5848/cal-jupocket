# 주포켓 리디자인 브리핑 — 글에서 계산기로 넘기는 버튼, 대출·지원금 축 (2026-11-07)

사용자가 질문을 건너뛰고 바로 시작하라고 했다. 아래에서 "사용자 결정"은 대화에서 사용자가 직접 말한 것, "내 판단"은 내가 정한 것이다.

## 왜 지금

- **2026-11-01부터 구글 검색 노출이 사이트 전체에서 99% 끊겼다**(하루 2,000~3,000 → 0~8). 나라·기기·페이지 전부 같은 날. 직접 조치 없음(사용자 확인), 크롤링·색인·canonical 정상, 제목을 따옴표로 치면 1위인데 따옴표 없이는 20위 밖, "jupocket" 브랜드 검색에도 사이트가 안 나온다 → 알고리즘에 의한 사이트 전체 강등으로 판단. 유력 원인은 10월 하순 12개국 판 대량 생성(내 판단, 구글은 이유를 알려 주지 않는다).
- 그래서 지금 오는 사람(28일 GA 세션 434, 대부분 직접 유입)에게서 더 많이 일어나게 해야 한다. **페이지/세션이 1.0~1.3** — 대부분 한 장 보고 나간다. 모바일 전면 광고(비네트)는 페이지를 옮길 때 뜨므로 이동이 없으면 광고도 거의 안 뜬다.
- 사용자 결정: 루틴 둘(나라판 배차·한국 도구)을 멈췄다(2026-11-07). 새 글은 **대출 금리**, 그다음 **정부·공공기관 지원 제도**. 글에서 **실제 디자인된 버튼**으로 **우리 계산기**로 보낸다. 계산기 중심인 홈도 다시 짠다.

## 목표

1. 글 → 계산기 이동을 눈에 띄는 버튼으로 만든다. 측정: GA4 `calc_click`(이미 있음)·페이지/세션. 목표 페이지/세션 1.6 이상(내 판단, 4주 뒤 확인).
2. 콘텐츠 축을 대출·이자 → 정부 지원 제도로 넓힌다(광고 단가가 높은 주제, 기존 돈·금융 계산기 9종과 바로 이어짐).
3. 홈을 "도구 도감"에서 **"고민 → 해설 → 계산기"** 입구로 바꾼다.

## 하지 않는 것 (안티 목표 — 이렇게 되면 기능이 돌아가도 실패)

- **속이는 버튼.** "신청하기"인데 신청이 아니라 다른 글로 가는 버튼, 버튼 문구와 도착지가 다른 것. 버튼은 도착지를 그대로 말한다("대출 이자 계산기로").
- **광고를 누르게 하는 장치.** "광고를 눌러 주세요", 광고 쪽 화살표, 광고 바로 위·아래에 붙은 버튼(잘못 누르게 됨). CTA와 `.ad-slot` 사이에는 본문 한 덩이 이상을 둔다.
- **징검다리 페이지.** 내용 없이 버튼만 있는 중간 페이지를 만들어 이동 수를 늘리지 않는다 — 지금 강등 원인과 같은 모양이다.
- **대량 생산.** 새 글은 적게, 숫자는 원문 확인(저장소 규칙 그대로).

## 1단계 — 계산기 버튼(CalcCta) — 지금 만든다

**모양(내 판단):** 본문의 조용한 톤 안에서 유일하게 "눌러도 되는 물건"처럼 보이는 상자 하나.
- 왼쪽: 질문 한 줄(독자의 고민) + 작은 설명 한 줄 / 오른쪽(모바일은 아래): 브랜드색 채운 버튼 "○○ 계산기로 →".
- 상자 배경 `--brand-wash`, 버튼 `--brand` 바탕 흰 글씨, 둥근 모서리 `--r-md`, 버튼 높이 48px 이상(손가락).
- 라이트·다크 둘 다 기존 토큰만 쓴다.

**자리(내 판단):**
- **중간:** 글 맨 위 "한 줄 답"(AnswerBox) 바로 아래 — 답을 읽은 직후 "내 경우는?"이 생기는 자리. AnswerBox 가 300편에 이미 있어서 한 곳만 고치면 붙는다.
- **끝:** 본문 끝, "이어서 볼 글"(NextReads) 바로 위.
- 계산기 페이지 자신(이미 계산기가 있는 글)에는 붙이지 않는다.

**어디로(내 판단):** 그 글이 속한 묶음(clusters.ts)의 계산기 중 가장 가까운 것. 질문 문구는 계산기마다 한 줄씩 등록부(`src/data/calc-cta.ts`)에 둔다 — 문구가 없는 계산기는 버튼을 그리지 않는다(어색한 기본 문구 대신). 대출 계산기 6종부터 문구를 채운다.

**측정:** 버튼에 `data-cta="mid|end"`. 기존 `calc_click` 이벤트에 `cta` 위치를 함께 보낸다(GA4 맞춤 측정기준 등록은 사용자 일).

**검사:** 등록부의 계산기 주소가 실제 계산기인지, 버튼 문구 길이, 계산기 페이지에 버튼이 안 붙는지 — vitest.

## 2단계 — 대출 글 도입부 (PASONA 중 P·A·S만)

대출 묶음 22편 중 유입 상위부터, 도입 2~3문장을 "문제 → 공감 → 해결(= 계산기)" 순서로 다시 쓴다. 숫자는 계산 함수로만. 한 회에 5편, 강등 중이라 천천히(내 판단).

## 3단계 — 정부 지원 제도 묶음

새 묶음 "지원금·정책대출": 주택도시기금(디딤돌·버팀목), 서민금융진흥원(햇살론 등), 청년 정책 상품. 각 글은 공식 기관 원문 확인 → 자격·한도·금리 표 → **우리 계산기**(대출 이자·DSR·중도상환)로 버튼. 제도 숫자는 rates JSON 에 출처·확인일. 신청은 공식 사이트로 가는 일반 링크(우리 버튼과 모양을 다르게 해서 헷갈리지 않게).

## 4단계 — 홈 개편

- 히어로: "무엇이 고민이세요?" + 고민 입구 카드 3장 — **대출·이자 / 지원금 / 세금·급여**. 카드마다 대표 질문 2~3개(글)와 대표 계산기 1개.
- 그 아래 검색(지금 것 유지), 그 아래 기존 도구 도감(접힌 상태로 아래로).
- 시안을 먼저 보여 주고 사용자 확인 후 만든다(사용자 결정: 홈은 다시 디자인).

## 남겨 둔 것 (만드는 사람 몫)

- 버튼 세부 여백·아이콘 유무, 문구 다듬기.
- 3단계 상품 목록은 키워드(자동완성·입찰가)로 순서를 정한다.
