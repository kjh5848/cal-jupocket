## 1. 목적

세금·급여 계산기 사이트였던 jupocket.com 을 **생활 도구를 다 담는 주머니**로 넓힌다.
roberin.com(432개)·utilo.co.kr(151개)이 다루는 도구를 목록으로 삼아 하나씩 담되, **기능만 참고하고 코드·문구·디자인은 우리 것으로** 새로 만든다.

성공 기준
- 기존 방문자에게는 같은 사이트로 보인다(배경·카드·글 페이지 그대로, 주소·번호 그대로).
- 첫 화면에서 검색 한 번으로 원하는 도구에 닿는다.
- 도구가 수백 개로 늘어도 분류·번호·검색으로 찾을 수 있다.
- 세금·급여 도구의 "법 원문으로 검증" 신뢰는 그대로 유지된다.

## 3. 바뀌는 화면

### 3-1. 헤더
- 로고: 3D 봉투형 주머니(SVG 원본). 크기 40px, 작게(16·32px)에서도 형태가 남는지 확인.
- 메뉴: `계산기 · 읽을거리 · 카드뉴스` → **`도구 · 읽을거리 · 카드뉴스`**

### 3-2. 홈 히어로 (UX 시안으로 교체)
- 화면 폭 파란 상자·배경 사진을 없애고 페이지 바닥 위에 바로 놓는다. 가운데 정렬, 폭 620px.
- h1: `주포켓`(작은 윗줄, 브랜드 파랑) + **뭐가 필요하세요?** / 설명: 세금·급여 계산부터 날짜·사진·문서까지, 담긴 도구에서 바로 찾아 쓰세요.
- **검색창이 주인공**: 높이 60px, 그림자 하나, 데스크톱은 `/` 키로 바로 입력(폰은 표시 숨김).
- 결과는 검색창 바로 아래 **겹쳐 뜨는 목록**(아래 내용을 밀지 않음). 한 줄 = 분류 색 점 · 이름(일치 부분 칠하기) · 한 줄 설명(분류 · 설명) · 오른쪽 도감 번호. 아래에 `↑↓ 고르기 · Enter 열기 · Esc 닫기`.
- 검색 전에는 **자주 찾는 말 버튼 5개** — 검색량 순(keyword-research 기록에서).
- **담긴 도구 수**: `도구 N개 담김 · M개 채우는 중` — N은 공개된 도구 수, M은 목록(roberin·utilo 중복 제거 후) 전체 수. 둘 다 레지스트리에서 계산.
- '인스타에서 본 번호 찾기 →' 링크 그대로.

### 3-3. 도구 도감 (지금 '계산기' 목록 자리)
- 제목: **도구 도감**
- 분류 뱃지 줄: 누르면 그 분류만 보이게(페이지 이동 없이 걸러 보기).
- 카드: 지금 카드 그대로 + **도감 번호(No.001)** + **분류 뱃지**.
- **아직 없는 도구 칸**: 점선 카드 `No.??? / ???` + "○○ — 곧 담깁니다". 다음에 만들 도구 4~8개만 보여 준다(전부 보여 주면 빈칸이 압도).

### 3-5. 모바일 (화면 초안에서 나온 조정)
- 진행 바 문구는 한 줄: `써 본 도구 3/21`.
- 분류 뱃지 12개는 줄바꿈 대신 가로로 넘겨 보는 한 줄.
- 히어로 위아래 여백을 줄여, 첫 화면에 검색창 아래 도감 첫 줄이 걸치게.
- 검색 결과 창은 키보드(↑↓·Enter)로도 고를 수 있게.

### 3-6. 계산기 틀 (공통 부품, UX 시안)
지금 계산기는 입력칸 하나가 약 82px 이라 폰에서 입력만으로 한 화면이 차고, 숫자를 바꿔도 결과가 화면 밖에 있다. 모든 계산기를 같은 틀로 다시 짠다.

| 부분 | 규칙 |
|---|---|
| 입력칸 | 높이 약 58px, 숫자 20px, 단위는 칸 안 오른쪽 |
| 금액 읽어 주기 | 금액 칸 아래 `3,600만원` / `1억 2,000만원` |
| 자주 넣는 금액 | 버튼 4개. **금액은 그 계산기의 자동완성에 붙어 나오는 금액**(지어내지 않음) |
| 고르기 | 선택지 2~3개는 드롭다운 대신 버튼(세그먼트). 4개 이상만 드롭다운 |
| 사람 수·개수 | − / + 버튼 |
| 결과 | 큰 숫자 + 구성 비율 막대(예: 실수령·4대보험·세금) + **영수증 목록**(항목 한 줄씩, 무리별 소계) |
| 결과 뒤 | 결과 복사 · 처음 값으로 |
| 데스크톱(900px 이상) | 입력 왼쪽 · 결과 오른쪽 두 칸, 결과는 스크롤해도 따라옴 |
| 폰 | 결과 카드가 화면 밖이면 아래 **고정 띠**(대표 결과 + '자세히 ↓') |

- 계산은 지금처럼 `src/lib/*.ts` 가 하고, 틀은 입력·결과 표시만 맡는다(계산기 스크립트는 값 읽기·결과 쓰기만 남는다).
- 계산기마다 roberin 의 같은 도구를 열어 **입력 순서·선택지·결과 항목**을 대조하고, 우리에게 없는 유용한 항목을 더한다(예: 3.3% 계산기의 부가세 포함 방향). 글·디자인·코드는 가져오지 않는다.
- 결과 복사·PNG 저장 등 지금 계산기에 있는 기능은 유지.

## 4. 데이터 구조

### 4-1. 도구 레지스트리 `src/data/tools.ts` (신설)
모든 도구의 한 줄 목록. 홈 도감·분류·검색·담긴 수가 전부 여기서 나온다.

```ts
export interface Tool {
  no: number | null;        // 도감 번호 = 링크허브 번호. 아직 없는 도구는 null
  href: string;             // 공개 주소
  name: string;             // 카드 제목
  blurb: string;            // 한 줄 설명
  type: ToolType;           // 3-4 분류
  keywords: string[];       // 검색 동의어(예: "실수령액" ↔ "월급 얼마")
  status: "live" | "next";  // next = 곧 담길 도구(점선 칸)
  verified?: "law";         // 법 원문 검증 도구 표시
}
```

- 기존 계산기 20개는 clusters.ts·linkhub.ts 에서 옮겨 온다(중복 원본을 두지 않도록 linkhub 를 기준으로 생성).
- 목록 전체(roberin·utilo)는 `docs/tool-backlog.md` 에 표로 두고, 만들 차례가 된 것만 `status: "next"` 로 레지스트리에 올린다.

### 4-2. 도감 번호
- **링크허브 번호를 그대로 이어 쓴다(링크허브의 다음 번호부터).** 인스타 캡션 "N번 글" 안내와 같은 체계를 유지한다.
- 번호 재사용·재정렬 금지(지금 규칙 그대로).
- 글과 도구가 한 번호 체계를 공유하므로 도감 번호가 듬성듬성하다(예: No.001, No.004, No.236). 도감의 '빈 번호'로 그대로 둔다.

### 4-3. 주소
- 기존 주소는 그대로.
- 새 범용 도구는 `/tools/<slug>/`. 세금·급여 계산기는 지금처럼 `/guide/<slug>/` 계산기 글 형식을 따른다.

## 5. 검색
- 클라이언트 검색(서버 없음): 레지스트리를 빌드 때 JSON 으로 내보내 브라우저에서 이름·설명·동의어를 매칭.
- 초성 검색(ㅅㅅㄹㅇ → 실수령액)과 띄어쓰기 무시.
- 결과는 도감 카드와 같은 모양. 결과가 없으면 "아직 없는 도구예요 — 곧 담길 목록" 과 함께 backlog 에 있는 이름이면 그 도구를 '곧 담깁니다'로 보여 준다.
- 자연어 검색(AI)은 범위 밖 — 동의어로 먼저 해결.

## 6. 디자인 테마

### 6-1. 게임화 — 도감 수집
- **내가 써 본 도구**: 계산기를 한 번 쓰면(지금 `trackCalculatorUse` 가 '사용'으로 보는 시점) 그 도구를 '수집'으로 기록. 그 브라우저의 localStorage 에만 저장, 로그인·서버 저장 없음.
- 홈 도감 위에 `내가 써 본 도구 3 / 20` 진행 바, 써 본 카드에 작은 도장 표시.
- 분류별 수집률은 분류 걸러 보기에서만 보여 준다.
- **하지 않는 것**: 연속 방문 압박, 알림, 리더보드, 보상 미끼 — 세금 사이트의 신뢰와 맞지 않고 '어두운 패턴'이 된다.

### 6-2. 3D 아이콘
- 로고와 같은 질감(위쪽 밝은 그라데이션 + 아래 두께 + 부드러운 그림자)으로 **분류 아이콘 12개**를 만든다. SVG, 무거운 3D 렌더링(WebGL) 없음.
- 카드 안의 기존 선 아이콘은 그대로 둔다(도구마다 3D를 만들면 563개 — 분류 아이콘만 3D).

### 6-3. 모션
- 결과 금액 카운트업(0.4초 이하), 카드 호버 살짝 뜨기, 처음 쓴 도구 '담기' 도장 애니메이션.
- `prefers-reduced-motion` 이면 모두 끈다(기존 대응 유지).

### 6-4. 손대지 않는 것
라이트 모드 배경 질감·색, 카드 모양·그림자, 글꼴, 글 페이지 레이아웃. (히어로 사진·계산기 레이아웃·다크 모드는 UX 시안으로 바뀐다.)

### 6-5. 다크모드
- 토큰 교체(지금 → 시안): 바닥 #121419 → #0d1220 · 카드 #1c2027 → #161d2e · 입력칸 #23282f → #222b40 · 선 #363c44 → #2f3a52 · 글자 #e8e8e8 → #e7ebf3 · 보조 글자 #a0a0a0 → #a9b3c7 · 링크 #6fb3ff → #8fb8ff.
- 다크에서는 바닥 알갱이 질감을 빼고 위쪽 남색 빛만. 도구 카드 아이콘 칸은 분류 색 22%만 섞는다.
- 결과 카드: 짙은 남색(#14213d) 대신 로고 파랑 그라데이션(라이트 #1a73d6→#0b4f9e, 다크 #2357a8→#173b78).
- `.qa-lead` 굵기 600 → 500, 줄 간격 1.8(라이트·다크 모두).
- **직접 전환 버튼**: 헤더 오른쪽에 라이트 / 다크 / 기기 설정 따르기. 고른 값은 localStorage(실패해도 기기 설정으로 동작), 첫 그림 전에 `<html data-theme>` 를 정하는 짧은 인라인 스크립트로 깜빡임 없게. CSS 는 `prefers-color-scheme` 와 `[data-theme]` 를 둘 다 받는 구조로 바꾼다.
- 대비: 본문·보조 글자 모두 카드 위 4.5:1 이상(시안 기준 13:1 · 7.6:1).

## 7. 브랜드 자산 교체

## 9. 테스트
- 레지스트리: 번호 중복·재사용 금지, linkhub 와 번호·주소 일치, 분류 12개 밖 값 금지.
- 홈: 담긴 수 = `status: live` 개수, 점선 칸은 `next` 만.
- 검색: 초성·동의어 사례 표 고정 테스트.
- 게임화: localStorage 접근이 예외를 던져도 홈이 렌더(try/catch).
- 계산기 틀: 금액 읽어 주기(만·억) 표 테스트, 프리셋 금액이 자동완성 기록에 있는지, 고정 띠가 결과 카드와 같은 값인지.
- 다크: 토큰 대비 테스트(본문·보조 글자 4.5:1 이상), 전환 버튼이 localStorage 예외에서도 동작.
- 기존 테스트(SEO·스니펫·링크허브·카드) 전부 통과.

## 10. 범위 밖 / 위험
- **저작권·상표**: roberin·utilo 의 코드·문구·화면을 복사하지 않는다. 포켓몬 시각 요소 사용 금지. 2026-10-16 사용자가 '그대로 베끼자'고 했으나 이 선을 유지하기로 하고 그대로 진행(기능·흐름만 벤치마킹, 나라별 숫자는 그 나라 원문 검증).
- **주제 희석**: 범용 도구가 늘면 '세금 사이트' 신호가 약해질 수 있다 — 세금·급여 글과 계산기는 지금 구조·주소를 그대로 두고, 범용 도구는 `/tools/` 아래에 분리.
- **검색 상위권 기대치**: 퍼센트·날짜 계산기 같은 범용어는 네이버 자체 계산기가 1위를 차지한다(v54). 볼륨보다 '들어온 사람이 다른 도구도 쓰게' 하는 쪽이 목표.
- 자연어(AI) 검색, 로그인·서버 저장, 리더보드는 하지 않는다.
