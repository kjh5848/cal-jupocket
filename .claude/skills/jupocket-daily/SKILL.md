# 하루치 콘텐츠 사이클

글 1편 → 인스타 카드뉴스 1세트 + 스레드 텍스트 여러 편.

이 저장소에서 **가장 먼저 무너지는 것은 숫자 검증**이다. 세금 사이트에서
검증이 무너지면 잃는 것은 순위가 아니라 신뢰이고, 한 번 나간 글은 회수할 수
없다. 실제로 2026-09-13 에 "작년까지 27년간 9%였습니다" 라는 검증 안 된
문장이 스레드로 나갔다. `pension-premium-2026.json` 에는 그 기간이 없었다.

그래서 이 사이클은 **검증을 통과하지 못하면 다음 단계로 못 가게** 짜여 있다.

관련 문서:
- **제작 순서 전체: `docs/CONTENT.md`** (이 스킬의 근거)
- 키워드 판단 이력: `docs/keyword-research.md` (v1~v4)
- 소셜 운영: `social/README.md`
- 발행 상태 보기: `npm run queue`

---

## 0. 먼저 상태를 본다

```bash
npm run queue
```

- 본문 링크 경고(`✖`)가 있으면 **먼저 고친다** — 그 글은 게시되지 않는다
- 스케줄러가 `꺼짐`이면 알리고, 켤지 묻는다

### 큐 상황은 스레드 편수만 정한다

**글과 카드는 큐 사정과 무관하게 매일 만든다.** 글은 웹페이지라 쌓여도
문제가 없고 검색에서 복리로 쌓인다. 조절할 것은 발행 간격이지 글을 쓰는
일이 아니다.

| 미발행 스레드 | 이번에 넣을 편수 |
|---|---|
| 0~2건 | 8~10편 |
| 3~5건 | 4~5편 |
| 6건 이상 | 넣지 않는다 — 글·카드만 만들고 다음에 채운다 |

큐에 있는 글은 **이미 쓴 블로그 글에서 뽑아낸 스레드용 짧은 글**이다.
블로그 글 자체와 혼동하지 않는다.

## 1. 주제를 고른다 — 무에서 고르지 않는다

`docs/CONTENT.md` 의 세 필터를 그대로 적용한다.

1. **검증된 클러스터 안쪽** — 종합소득세·원천징수 / 부가가치세 / 노후·연금.
   새 축은 SERP 문서 총량을 직접 확인한 뒤에만 연다
2. **CPC·경쟁** — head 계산기 회피(퇴직금계산기 월 29만인데 입찰가 ₩17),
   설명 콘텐츠 우선(CPC ₩1,300~3,300)
3. **캘린더** — 1월 부가세·연말정산 / 5월 종소세 / 7월 부가세. 신고철 3~4주 전

**남은 빈칸을 먼저 쓴다.** `docs/CONTENT.md` 의 "지금 비어 있는 칸" 표를 본다.
소진되면 새로 파되, 채택하면 `docs/keyword-research.md` 에 v5로 **append**
한다(덮어쓰지 않는다 — 판단 이력이 근거다).

**같은 주제를 두 번 쓰지 않는다.** `src/data/clusters.ts` 의 기존 14편 제목과
`social/queue/*.md` 의 첫 줄을 대조한다.

## 2. 숫자를 검증한다 — 여기서 막히면 멈춘다

글에 들어갈 **모든** 요율·금액·기한은 `src/rates/*.json` 에 있어야 한다.

없으면 원문에서 확인해 추가한다:
- **국가법령정보센터 법령 원문** (최우선 — 시행일까지 나온다)
- **국세청** 세법 안내
- **국민연금공단** 공식 안내

`sources`(URL) + `verifiedOn` 필수.

### 절대 하지 않는 것

- **원문에서 확인 못 한 숫자를 쓰지 않는다.** "대략", "보통", 상식으로 아는
  값 전부 포함. 가산세율이 아직 빈칸인 이유가 이것이다
- **뉴스·블로그의 숫자를 그대로 옮기지 않는다.** 재가공본을 옮기면 오보를
  그대로 옮긴다. 발견은 뉴스로 하되 **반드시 원문을 다시 연다**
- **이전 연도 값을 추론하지 않는다.** rates 에 2026년 요율만 있으면
  "작년엔 9%였다" 라고 쓸 수 없다

검증이 안 되면 **거기서 멈추고 사용자에게 무엇이 막혔는지 말한다.**
추측으로 채우지 않는다.

## 3. 글을 쓴다

`src/pages/guide/<slug>/index.astro`

- 금액은 **손으로 적지 않고** `src/lib/*.ts` 계산 함수로 뽑는다
  (`compute()`, `rateSchedule()` 등)
- 독자는 직장인·사장님·자영업자·프리랜서 전부. 프리랜서 전용 어휘로 좁히지
  않는다
- `updated` 는 rates 의 `verifiedOn` 과 같은 실제 확인일. 지어내지 않는다

## 4. 클러스터 등록 + 링크허브 번호

**번호가 카드보다 먼저다.** 카드의 `cta.refNo` 가 가리킬 대상이 있어야 한다.

`src/data/clusters.ts`
- 해당 클러스터 `links` 에 추가(`kind: "guide"`, `icon`)
- `recent` 맨 앞에 href
- **연도에 따라 숫자가 바뀌는 글이면 `year: 2026`**

`src/data/linkhub.ts`
- `nextNo()` 가 주는 다음 번호. 해당 `hubGroups` 에도 넣는다
- **번호는 재사용·재정렬 금지.** 이미 나간 캡션이 그 번호를 가리킨다
- 라벨은 **30자 이내**, 연도 붙이지 않는다

## 5. 인스타 카드뉴스 1세트

`src/data/cards.ts` 의 `cardSets`

- 카드 5~6장, `kind: cover | list | table | note | cta`
- **첫 장은 `cover`**(사진 표지), 마지막은 `cta` 에 4단계의 번호
- `link` 는 **글 주소**여야 한다(계산기 아님). 테스트가 `refNo` 와 대조한다
- 강조는 `[[형광펜]]` / `{{경고}}` — `text` 에만 쓴다. `detail` 은 원문
  그대로 나가서 중괄호가 그대로 보인다
- 안쪽 카드는 **밀도가 강점**이다 — 조밀한 표·번호 목록·출처 표기.
  얇게 만들지 않는다

### 첫 장은 목차가 아니라 멈춤장치다

넘길지 말지를 0.5초에 정하는 자리다. 읽을거리가 아니다.

**세 가지를 통과해야 한다.**

1. **무슨 얘기인지 0.5초에 잡히나** — 뱃지에 세목을 박는다
   (`종합소득세 · 부가세`). 이게 없으면 "4만원"이 세금인지 구독료인지
   알 수 없다
2. **안 보면 뭘 잃나** — 기한이 걸린 혜택, 놓치면 사라지는 것.
   "얼마를 문다"보다 "지금 하면 깎이는데 기한이 있다"가 세다
3. **분류로 시작하지 않는다** — "A는 두 종류가 있습니다" 는 글의 첫
   문단이지 카드의 첫 장이 아니다

실제로 겪은 예:

| | |
|---|---|
| ✗ 약함 | "가산세는 두 개가 따로 붙는다" — 구조 설명. 왜 신경 쓸지를 안 말한다 |
| ✗ 애매 | "30일과 31일, 4만원 차이" — 무엇에 대한 4만원인지 없다 |
| ✓ | "신고 놓쳤어도 **가산세는 깎입니다**" + "1개월 안이면 50%, 6개월 지나면 한 푼도 안 깎입니다" |

부제에 숫자와 기한을 넣는다. 그리고 **부제가 틀리면 안 된다** — "가산세
50% 감면"처럼 뭉뚱그리면 납부지연가산세까지 깎이는 것으로 읽힌다.

### 표지 사진

`anthropic-skills:stock-image-fetch` 스킬로 구한다. `public/photos/` 에
두고 `photo: "/photos/card-<주제>.jpg"` 로 건다.

- **흑백·저채도**를 고른다. 브랜드색과 형광펜이 그 위에 얹힌다
- **연도·날짜가 박힌 컷을 피한다** — "2016" 이 찍힌 다이어리를 쓰면 바로 낡는다
- **태그만 보고 고르지 않는다.** 미리보기를 받아 눈으로 본다. 백색 배경
  인물 컷 같은 전형적인 스톡 사진은 우리 톤과 안 맞는다
- 세로(vertical)로 검색한다 — 카드가 4:5다

## 6. 스레드 텍스트

`social/queue/NNN-<slug>.md` — 0단계 표가 정한 편수만큼

```markdown
---
at: "09:00"
reply: 한 줄 요약. 프로필 링크에서 N번 글입니다 → jupocket.com/link/
---
첫 줄이 후킹. 링크는 절대 넣지 않는다.
```

### 각 편이 서로 다른 "사실"을 담아야 한다

표현만 바꾼 중복은 Threads 가 반복 게시로 보고 도달을 깎는다. 같은
타임라인을 보는 사람에게도 역효과다.

국민연금 글 한 편에서 나온 10각도(실제 예시):
요율 / 2033년 13% 일정 / 직장인 vs 지역가입자 / 상한 659만 / 하한 41만 /
7월 조정 / 두 번의 절사 / 납부예외 신청 / 납부예외의 대가 / 상한 실효율

**첫 줄이 전부 달라야 한다.** 기존 큐와 발행본의 첫 줄을 대조한다:

```bash
for f in social/queue/*.md; do
  printf "%-34s %s\n" "$(basename $f .md)" \
    "$(sed -n '/^---$/,/^---$/!p' "$f" | grep -v '^$' | head -1)"
done
```

### 시간대 — 기존 큐는 건드리지 않는다

**이미 큐에 있는 글의 `at:` 도, 파일명도 바꾸지 않는다.** 예약된 순서가
있고, 번호를 흔들면 어느 것이 나갔는지 추적이 깨진다.

새 글은 **비어 있는 슬롯**에만 넣는다. 쓰는 슬롯은 이것뿐이다:

`07:30 09:00 11:00 12:30 14:00 16:00 18:00 19:30 21:00 22:30`

`npm run queue` 로 미발행 글이 어느 시각을 쓰고 있는지 보고, **남은 시각을
이른 것부터** 채운다. 같은 시각에 둘을 넣으면 하나는 30분 뒤로 밀리는데,
90분 유예 창을 넘기면 그날은 안 나간다.

파일명 번호(`NNN-`)는 **현재 최대 + 1** 부터 이어 붙인다. 기존 번호를
재사용하지 않는다.

### 링크는 두 번째 스레드부터

본문에 링크가 있으면 도달이 죽는다. `threads-post.mjs` 가 `link:` 와 본문
URL을 **게시 전에 거부**하지만, 애초에 넣지 않는다.

### 답글 링크는 반드시 `jupocket.com/link/`

`jupocket.com` 만 쓰면 스레드가 홈으로 링크를 건다. 그런데 답글 문구는
"**N번 글입니다**" 라고 말한다 — 번호 목록이 없는 페이지에 떨어뜨리는
것이다. 번호를 찾는 색인은 `/link/` 하나뿐이다.

같은 문장이 인스타 캡션으로도 나간다. 캡션에서는 URL이 눌리지 않으니
"프로필 링크에서" 라는 안내가 필요하고, 스레드에서는 그 URL이 눌린다 —
그래서 두 조각이 다 있어야 한다.

`npm run queue` 가 미발행 글의 답글 링크를 검사한다. 이미 나간 글은
고칠 수 없으므로 경고하지 않는다.

## 8. 카드 이미지


- 이미 발행한 세트를 다시 뽑는 것(`--all`, `--set`)은 **사용자에게 묻는다**
- 뽑은 뒤 갤러리에 실제로 뜨는지 본다. 축소 아트보드가 보이면 못 찾은 것

## 10. 게시 — 손댈 것 없다

스케줄러(`scripts/post-due.cmd`)가 30분마다 돌며 알아서 올린다.

- **스레드**: `at:` 시각이 된 것 하나. 90분 유예 창을 넘기면 내일로 넘긴다
- **인스타**: 하루 한 건. 같은 날 여러 개면 게시물당 도달이 나뉜다

큐에 넣고 이미지를 배포하면 끝이다. 배포가 안 끝났는데 시각이 되면
메타 서버가 이미지를 못 받아가므로 9단계의 200 확인을 건너뛰지 않는다.

손으로 올려야 할 때만:

```bash
npm run social:post -- --file NNN-….md --publish
npm run ig:post -- --file NNN-….md --publish
```

## 하지 말 것

- **검증 안 된 숫자 쓰기** — 이 저장소에서 가장 중요한 규칙
- **경쟁 블로그 캡처·민간 기업 보도자료 사진 사용** — 출처 표기는 라이선스의
  조건이지 대체물이 아니다
- **링크허브 번호 재사용·재정렬**
- **본문에 링크 넣기** (스레드)
- **표현만 바꾼 중복 글** — 도달이 깎인다
- **날짜 지어내기** — `updated` 도 `verifiedOn` 도 실제 확인일만

## 막히면 멈춘다

숫자를 확인할 수 없거나, 주제 재고가 없거나, 기존 글과 겹치면 **추측으로
채우지 말고 사용자에게 무엇이 막혔는지 말한다.** 하루 거르는 것이 잘못된
숫자를 내보내는 것보다 낫다.
