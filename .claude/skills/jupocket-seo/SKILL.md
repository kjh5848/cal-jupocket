# 검색 유입 점검

`npm run seo` 한 줄이면 숫자는 나온다. 이 스킬의 일은 **그 숫자를 틀리게 읽지 않는 것**이다.

이 저장소에서 검색 데이터는 특히 잘못 읽히는데, 이유가 셋이다 — 한 도메인에 성격이
다른 콘텐츠가 세 벌 올라가 있고, 두 서비스의 최신성이 다르며, "권한 없음"과
"데이터 없음"이 똑같이 빈 화면으로 보인다. 아래 순서는 그 셋을 차례로 걷어낸다.

관련 도구:
- 스크립트: `social/seo.mjs` (`npm run seo`)
- 소셜 게시물 성과: `npm run stats` — **다른 지표다**(아래 참고)
- 콘텐츠 제작: `jupocket-daily` 스킬

---

## 0. 먼저 연결부터 확인한다

```bash
npm run seo -- --check
```

정상이면 이렇게 나온다:

```
Search Console 접근 가능한 속성 1개
  · sc-domain:jupocket.com  [siteFullUser]
GA4 속성 399261686 접근 ✓ (세션 24)
```

**이 단계를 건너뛰지 않는 이유**: GSC 는 권한이 없어도 오류를 내지 않고 그냥 빈
결과를 준다. 데이터가 없는 것과 구분이 안 된다. 속성 목록이 `0개`로 나오면 그건
"검색 유입이 없다"가 아니라 "볼 자격이 없다"는 뜻이다.

막히면 3단계(진단)로 간다.

---

## 1. 숫자를 받는다

```bash
npm run seo              # 최근 28일
npm run seo -- --days 7  # 기간 변경
```

세 덩어리가 나온다 — GSC 검색어 25개, GSC 페이지 20개, GA4 방문 페이지 20개.

### 기간이 두 개인 것은 버그가 아니다

출력 머리에 기간이 둘 찍힌다:

```
기간   GSC 2026-08-15 ~ 2026-09-12 (지연 3일) · GA4 2026-08-18 ~ 2026-09-15
```

GSC 는 집계가 2~3일 늦어서 어제까지 달라고 하면 빈 날이 섞인다. GA4 는 거의
실시간이다. **한쪽 지연을 양쪽에 적용하면 최근 며칠이 통째로 빠진다** — 실제로
그렇게 두었다가 트래픽이 있는데도 GA4 세션 0 으로 보고한 적이 있다(2026-09-15).
두 기간이 어긋나 보이는 건 정상이고, 그래서 두 숫자를 직접 나눗셈하면 안 된다.

## 2. 해석한다 — 여기가 이 스킬의 본체

### 도메인 속성은 세 사이트를 한 통에 담는다

`sc-domain:jupocket.com` 은 서브도메인까지 전부 덮는다. 그 안에 **성격이 완전히
다른 콘텐츠 세 벌**이 들어 있으므로, 합계만 보고 판단하면 반드시 틀린다.

| 무엇 | 어디 | 정체 |
|---|---|---|
| 영어 의료보험 거절 | `/insurance-claims/...` | `adsens-static` 저장소 |
| 한국어 세금·계산기 | `cal.jupocket.com/...`, `/guide/...`, `/vat/` 등 | 이 저장소(cal) |
| 옛 워드프레스 글 | `/명절-선물-...`, `/정보처리산업기사-...` | 남아 있는 레거시 |

**항상 셋으로 나눠서 보고한다.** "노출 127" 같은 합계는 정보가 아니다 — 어느 쪽이
몇인지가 정보다. 스크립트가 `https://jupocket.com` 접두어를 지워서 출력하므로,
`/` 로 시작하는 경로는 전부 jupocket.com 이고 `cal.jupocket.com` 만 따로 찍힌다.

### 평균순위를 읽는 법

1페이지는 대략 1~10위다. 그 아래는 이렇게 읽는다:

- **60~100위**: 6~10페이지. 색인은 됐고 순위가 없는 상태다. 클릭 0 이 당연하다 —
  "왜 클릭이 없지"가 아니라 "아직 순위가 안 붙었다"가 맞는 해석이다.
- **20~40위**: 2~4페이지. 조금만 밀어도 올라올 수 있는 구간이라 **가장 값싼 기회**다.
- **10위 내외**: 클릭이 나와야 정상이다. 노출은 있는데 클릭이 0 이면 제목·설명이
  검색 의도와 안 맞는 것이므로 그쪽을 본다.

**보고할 때 순위가 좋은 것부터 짚는다.** 노출 순으로만 나열하면 "노출 56, 80위"가
맨 위에 오는데 그건 당장 할 게 없는 항목이다. 정작 움직일 수 있는 건 노출이 적어도
순위가 앞선 쪽이다. (2026-09-15 실제 예: 노출 127개 중 `co 115 denial code` 단
1노출이 10위로, 유일하게 손댈 가치가 있는 자리였다.)

### 클릭 0 을 실패로 단정하지 않는다

새 글은 색인 → 노출 → 순위 → 클릭 순서로 늦게 온다. 발행 며칠 된 글이 노출만
있는 건 정상 경로다. **글을 쓴 날짜와 대조해서 말한다** — `git log` 로 해당 글의
발행일을 보면 "아직 이른 것"과 "묻힌 것"이 갈린다.

### GA4 는 유입 경로를 본다

방문 페이지에서 특히 두 개를 본다:

- **`/link`** — 스레드 프로필 링크에서 넘어온 사람이다. 소셜 도달이 실제 방문으로
  이어졌는지가 여기 찍힌다. 체류가 짧으면(10~20초) 링크허브에서 글로 못 넘어가고
  이탈한 것이다.
- **`/`** — 홈. 체류가 길면 사이트 자체는 붙잡고 있다는 뜻이다.

`(not set)` 행은 방문 페이지를 못 잡은 세션이라 해석하지 않는다.

### `npm run stats` 와 섞지 않는다

- `npm run stats` = **우리가 밀어서 온 사람** (스레드·인스타 조회·좋아요)
- `npm run seo` = **검색으로 찾아온 사람**

둘은 모수도 성격도 다르다. 같은 표에 넣거나 비율을 내면 무의미한 숫자가 나온다.
다만 한 방향으로는 이어진다 — 스레드 도달이 큰데 `/link` 세션이 적으면
"도달은 되는데 유입이 안 된다"는 결론이 서고, 이건 말할 가치가 있다.

## 3. 막혔을 때 진단

### `✖ 키 파일이 없습니다`

`.secrets/google.json` 이 없다. GCP 콘솔 > IAM 및 관리자 > 서비스 계정 >
`jupocket-analytics` > 키 > 키 추가 > 새 키 만들기 > JSON.

**비공개 키는 대신 받아주지 않는다.** 자격증명이라 사용자가 직접 내려받아
`.secrets/google.json` 으로 옮기게 하고, 파일 내용을 열거나 출력하지 않는다.
`.secrets/` 는 `.gitignore` 에 걸려 있다 — 커밋되지 않는지 확인만 한다:
`git check-ignore -v .secrets/google.json`

### `✖ 토큰 발급 실패`

GCP 프로젝트(`kr-keyword-pipeline`)에서 API 두 개가 꺼져 있을 때 난다.
Google Analytics Data API · Google Search Console API 를 사용 설정한다.

### GSC 속성 목록이 `0개`

권한이 없다. search.google.com/search-console > 설정 > 사용자 및 권한 에서
서비스 계정 주소를 **전체** 권한으로 추가한다. 추가는 사용자가 한다 —
데이터 접근 권한을 바꾸는 일이라 임의로 하지 않는다.

### `✖ GA4 접근 실패`

GA4 > 관리 > 속성 액세스 관리 에 서비스 계정이 **뷰어**로 없다.

`GA4_PROPERTY_ID` 는 **측정 ID(`G-...`)가 아니라 숫자**다. 헷갈리기 쉬운데,
GA4 주소창의 `.../pNNNNNNNNN/...` 에서 `p` 뒤 숫자이거나 관리 > 속성 설정에 있다.

### 설정값이 어디 있나

| 값 | 위치 |
|---|---|
| 서비스 계정 비공개 키 | `.secrets/google.json` (gitignore) |
| `GA4_PROPERTY_ID` · `GSC_SITE_URL` | `.env` (gitignore) |
| 설명·예시 | `.env.example` (커밋됨) |

## 4. 보고

한국어로, 사실만. 원본 표를 그대로 붙여넣지 말고 **읽은 것**을 쓴다:

- 세 콘텐츠 축이 각각 몇 노출인지 (합계만 쓰지 않는다)
- 순위가 가장 앞선 검색어와 그 위치 — 움직일 수 있는 자리
- 노출이 큰데 순위가 뒤인 것 — 지금은 할 게 없다는 것까지 같이 말한다
- GA4 `/link` 세션과 체류 — 소셜 유입이 실제로 붙는지
- 지난번 실행과 비교할 것이 있으면 변화 (없으면 이번이 기준선이라고 말한다)

**숫자를 지어내지 않는다.** 스크립트가 낸 값만 쓰고, 기간이 짧아 판단이 이른
항목은 "아직 이르다"고 적는다. 색인이 며칠 안 된 글에 결론을 내리는 것이 이
저장소에서 가장 흔한 오독이다.

---

## 5. 읽은 것을 판단 이력에 남긴다

여기서 끝내면 다음번에 같은 키워드를 또 후보로 올린다. **읽을 값이 나왔으면
`docs/keyword-research.md` 맨 아래에 새 절로 append 한다.**

남길 것은 표가 아니라 **판정**이다:

- 노출이 붙기 시작한 검색어 — 그 축을 더 팔 근거
- 글은 있는데 노출이 없는 검색어 — 제목·소제목이 검색어와 어긋났을 수 있다
- 기대했는데 아예 안 걸린 것 — 다음 후보에서 뺄 이유

한 바퀴는 이렇게 돈다. 이 스킬은 마지막 칸이면서 동시에 다음 바퀴의 입력이다:

```
keyword-tools (발굴·조회) → keyword-research.md (판정) → jupocket-daily (글)
      ↑                                                        ↓
      └──────────────────  이 스킬 (확인)  ←────────────────────┘
```

**아직 이른 것은 남기지 않는다.** 색인 며칠짜리 숫자를 판정으로 적으면 그게
다음 판단을 망친다.
